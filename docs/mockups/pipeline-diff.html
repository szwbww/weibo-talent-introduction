两个必须配套的东西，否则会出新问题：
① 确定性 —— 关键词是确定的，LLM 不是。必须 temperature=0 + 按 (sourceVersion, 规则集哈希) 缓存检索结果，否则 evidenceSetVersion 会漂，工作台不停提示"事实已变化"。
② 兜底用并集不是替代 —— 关键词命中的必进，保住确定性下限；LLM 超时或挂了，最坏退化成今天的行为，不会更差。
最硬的一条约束（要先定）：requestKey = sha256(sourceVersion, index, requestText, intentKeys)。 intentKeys 在哈希里，所以只要动 intent 目录（删死键、补 alias、改 coverage 归属）， trust_reply_workbench_state（V83）里的历史锁定项就会全部失配。 两条路：保持 intentKeys 的取值口径不变（只改怎么用、不改算出什么），或接受一次性 state 迁移。
