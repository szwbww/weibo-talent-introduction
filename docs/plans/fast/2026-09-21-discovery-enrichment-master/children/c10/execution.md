So the URL chain tries at most 3 addresses (third failure ⇒ the fourth is never accessed) and the paper can still do the bounded XML attempt first. Documented in the code KDoc.
- **`downloadAttempts` is carried by the existing `httpRequests`/`apiRequests` counter** instead of a new `details_json` key: `SourceStats.kt` is not in the authorized file list, so no new per-source numeric key was added. The invariant that matters — attempts counted separately and one paper never counted as two — is enforced in `consumeOutcome` (`papersSearched`/`fulltextAttempted` stay per paper, `apiRequests` accrues the per-attempt count) and asserted by `one paper with two download attempts counts one paper and two requests (V-1, I-3)`. The failure *categories* (the only new names the plan requires in `details_json`) do appear there via `failureReasons`.
- **`UnpaywallClient.findPdfUrls` added** (the plan says "必要时调用既有Unpaywall" / "DOI→Unpaywall开放位置"): the existing single-URL method could not express "other open locations", so the authorized client file gained a list variant; `findPdfUrl` keeps byte-for-byte behaviour (first public location) for its existing Crossref consumer.
- **c1 O-1 wiring shape**: the download site reports provider headers to the policy only when they actually carry the OpenAlex quota header (Bearer is scoped to the configured origin, so this is the only origin that can produce them). Deliberately *not* wired: a `beforeRequest` reservation for external-host downloads — releasing such a reservation requires `recordResponse(emptyHeaders)`, which would charge a phantom credit and grow the conservative backoff on every PDF download (throughput regression). No behavior is fabricated and the counter now has a real production writer.
