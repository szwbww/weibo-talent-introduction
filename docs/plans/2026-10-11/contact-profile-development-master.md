# 专家列表联系详情｜详细开发总计划

日期：2026-10-11。状态：**待评审，尚未实施**。依据：用户指定截图区域、Excel字段、已展示线上独立预览、视频可命名与单文件上限1G的补充要求。

## 需求描述

在「专家列表 → 右侧专家引进状态与联系详情 → 联系详情」完成以下可观察结果：

1. 表格19列有对应展示：姓名、国籍、关键词复用已有数据；16项人工资料新增。另增加科研能力、匹配企业进度、匹配到的企业，合计 **19个新增业务字段**。
2. 同一区域可看当前联系记录的收发件箱备注；无contact专家显示明确空态。
3. 支持多个会议视频、每个最大 **1 GiB（1024 MiB，1,073,741,824字节）**；上传前设置文件名、上传后重命名、播放及下载，扩展名固定。
4. 有联系记录、未联系专家两种详情路径都可用；保存后刷新仍保留。

必须保持：左右分栏/四个标签/默认标签和列表筛选；原邮件、阶段、会议安排、材料与简历规则；收发件箱备注归属与编辑；旧手动材料100MiB及回复附件10MiB限制。

范围外：自动导入Excel、修复Excel错位内容、企业主数据系统、AI评级、新字段全库搜索、视频转码/封面/删除、对象存储、分片续传、页面大重构。本次只写开发计划，不执行代码/迁移/正式发布。

### 字段清单与设计取舍

| 分组 | 新增业务字段 |
|---|---|
| 身份基本信息 | 人才编号、中文译名、出生日期/年份、护照/证件号、来源国家 |
| 教育任职 | 毕业学校、学校排名、来华前单位、单位排名、博士后单位、博士后年限、职称、行政职务/头衔 |
| 产业技术 | 产业领域、技术专长、申报类别 |
| 科研与企业匹配 | 科研能力、匹配企业进度、匹配到的企业 |

科研能力：很强 / 强 / 中上 / 中等 / 一般 / 低，未选为“未评估”。匹配进度：未匹配 / 匹配中 / 匹配上；匹配上必须至少一家企业。企业以多行名称保存，先不建设企业库或跨模块关联表。

Excel P列表头为空，“产业领域”是明确标注的暂定标签；S列保留自由文本，不猜QM/BS/BSH/HJ含义。只审字段，不导入90行中的证件等真实个人数据。详细长度/类型/空值/枚举以01为准。

预览文件不作为正式代码直接替换app.js。对预览建议的收敛：备注首版只读；企业采用单行一家的文本列表；视频从头重传，暂不分片；所有正式新增字段持久化，预览原内存试填不迁移。

## 关键不变量

### Invariant I-1: 专家与联系人身份分开
- Rule: 人工档案/视频按规范化逻辑expertId存；备注按真实contactId读。无contact不自动建联系记录；不猜ES_id，不合并campaign备注。
- Applies to: 01–05所有读写、页面切换。
- Violation consequence: 选错用户截图路径、串人或被迫发送邮件才能存资料。
- 来源: K-expert-detail-two-panel-render-sites、K-expert-contact-two-write-sites、K-bound-expert-cross-campaign-read。

### Invariant I-2: 新私有存储单一所有者
- Rule: 仅新建expert_manual_profile、expert_meeting_video两张业务表，分别一个写服务；已有expert_contact、ES、材料、备注表新增字段数0；不靠JSON/EAV规避范围限制。
- Applies to: 01/04 schema及service。
- Violation consequence: 自动流程覆盖人工值，影响材料完成度。
- 来源: K-expert-document-ownership-chain、本次代码审计。

### Invariant I-3: 逐字段与样式契约
- Rule: 新字段逐项服从01 I-5–I-23；元数据/视频状态服从04与05；新DOM/CSS只使用02/03/05逐字契约；所有失败/并发状态有可见结果。
- Applies to: 全部子计划。
- Violation consequence: 字段被误解释、保存失真、真实界面偏离约定。
- 来源: 用户需求、create-p。

### Invariant I-4: 大文件真实边界
- Rule: 新视频raw流上传1GiB、64KiB读取缓冲、两并发上限、旧multipart不变；自定义名称与UUID存储分离；Range受鉴权。没有真实1GiB验收证据不得声称上线完成。
- Applies to: 04/05实现、测试与发布。
- Violation consequence: 前端能选但服务器拒绝、内存增长或改名破坏播放。
- 来源: application.yml、Tomcat与Spring源码审计。

### Invariant I-5: 小计划串行、证据不冒充完成
- Rule: 01→02→03→04→05，每份独立验证后再继续。共享app.js/styles.css/index.html与Flyway IT不能并行改。计划完成≠代码完成，机器通过≠人工验收完成。
- Applies to: 执行、验证、验收、发布。
- Violation consequence: 共用文件覆盖、回归归因失败。
- 来源: create-p。

## 现状审计

完整审计与逐字源码见 [contact-profile-audit.md](contact-profile-audit.md)，有grep命令/退出码、所有匹配路径、源码SHA256、运行环境只读回执。关键结论：

- app.js:11213的showExpertDetail和:11656的loadContactDetail分别渲染同一contact标签；必须改两处。
- 既有备注和材料都绑定contactId；expert_contact只有campaign+orcid联合唯一，不能当专家唯一档案表。
- ES mapping dynamic=false；新字段不应直接塞前端payload后假设会自动持久化。
- application.yml:24–25 multipart仍100MB/101MB；线上本机为Tomcat直接监听80/443。新增raw视频接口可保留旧限制，不猜测存在nginx、不凭空加代理配置。
- Spring5.3.31源码明确有Resource Range支持，复用它并通过真实HTTP验证。
- 全部新store读写、跨模块交互与人工验收映射分别在各子计划；任何未触碰旧写路都明确保持，不宣称改造整条邮件/材料链。

### A-2：已有联系人与备注同步
- 前置条件: 测试联系人有收发件箱、旧材料和会议安排。

- 前置条件: 准备精确1GiB测试MP4和1GiB+1字节文件，具有测试上传权限和磁盘容量。
