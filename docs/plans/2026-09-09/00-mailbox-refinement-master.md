状态：待实施；本任务只形成计划，不代表授权发布。日期：2026-09-09。采用 create-p。设计依据和代码证据见 [审计](mailbox-refinement-audit.md)。

## 需求描述

交付已确认预览对应的生产收发件箱修复：紧凑专家会话、独立专家管理、符号筛选入口、行内翻译和真实邮件标签、可靠滚动恢复；补齐“全部”待处理优先。

| 编号 | 可观察结果 |
|---|---|
| R1 | 全部：有待处理来信的专家在前；每组按最近来信倒序；无来信最后。关注：最近来信倒序。待处理：只含待处理专家，最近来信倒序。 |
| R2 | 仅保留全部/关注/待处理三个 tab；搜索框右侧只有 ⋯，筛选默认隐藏。 |
| R3 | 专家状态、层级、标签在固定头部显示摘要，管理弹层编辑，不占消息滚动区。 |
| R4 | 邮件无原始正文/翻译正文/技术信息嵌套区；正文下直接翻译；来信可添加/移除邮件标签并标记已处理。 |
| R5 | 从专家列表进入，无缓存定位最新邮件、有缓存恢复；切换/加载更早/普通刷新不乱跳不串信。 |
| R6 | 可信工作台位于往来信件下、默认折叠，人工回复默认展开，真实发送/采用草稿/附件入口保留。 |
| R8 | 专家列表收发数量右侧显示真实专家标签；固定单行，超出省略，鼠标悬停显示完整标签；列表卡片不显示“待处理”标记，保留tab筛选与待处理优先排序。 |
| R7 | 邮件摘要、标题、人工回复主题不再显示合法 MIME encoded-word 编码串；历史记录也可读。 |

必须保留：M1 生产导航/登录/检查回复/批量发送/自动回复；M2 关注按登录用户隔离；M3 人工回复账号/目标/QA审计和手工草稿保护；M4 ExpertMaterials共享组件及附件按需获取；M5 任务记录钻取仍走现有旧列表及过滤；M6 既有专家管理与来信汇总标签写入语义。

不做：附件下载/检查回复性能第二轮重构、AI/QA规则重构、全站UI换肤、发件标签新表、待专家回复API删除、历史库批量主题回填、新前端框架。仅发件专家保留，只取消“待专家回复”功能入口。

## 关键不变量

### Invariant I-1: 排序只看真实待处理和来信
- Rule：pending = 同账号范围内 processing.process_status=MANUAL_REVIEW 的数量>0；全部排序 `(pending?0:1, 最近来信为NULL?1:0, 最近来信DESC, contactIdDESC)`；关注/待处理不加额外待处理优先。排序在DB分页之前；页面禁止sort。
- Applies to：01 repository page/explain；02 tab参数、标记/撤销/刷新读取。
- Violation consequence：跨页漏排、发件推高、误用专家状态。
- 来源：用户最新明确指令；K-group-before-pagination（仅继承先聚合后分页，撤销旧知识“会话必须按事件时间”绝对表述）。

### Invariant I-2: 单一来源与身份
- Rule：来信仅linked processing，发件仅OUTBOUND mail_record；消息身份source:id；标签/处理用processing.id，关注用session username+contactId。
- Applies to：全部新读取、标签动作、mark动作、缓存。
- Violation consequence：重复计数、标签串邮件、跨用户关注。
- 来源：K-mailbox-inbound-source-authority、K-mail-record-source-inbound-id。

### Invariant I-3: 样式与生产宿主有唯一契约
- Rule：02完整CSS/DOM为执行合同；导航及共享工作台/资料组件沿用生产；新样式只限mailbox范围；预览数据和window.fetch拦截不可进入生产。
- Applies to：02全部前端修改，03缓存发布注册。
- Violation consequence：实现偏差或生产接口被mock替代。
- 来源：用户；K-panel-bg-token-is-translucent。

### Invariant I-4: UI操作不丢上下文
- Rule：浏览不标记已处理；标签/翻译只改对应消息；未缓存定位最后一封消息，不定位编辑器；已缓存恢复锚点；晚响应需校验用户/contact/account/request序号。
- Applies to：02选择、focus、翻页、刷新、标签、翻译、管理、unmount。
- Violation consequence：跳错位置、串信、覆盖草稿。
- 来源：原始；K-shared-workbench-fixed-mode-host-adapter。

### Invariant I-5: 沿用业务写入
- Rule：不改变SMTP、QA审计、附件获取、状态/层级服务及关注存储；失败不能伪成功；复用真实接口而非预览数组。
- Applies to：01仅解码新邮件subject；02宿主调用现有写入。
- Violation consequence：生产状态不持久化/误发/下载大量附件。
- 来源：K-relocated-control-refresh-owner、K-expert-tag-editor-shared-render-contract。
