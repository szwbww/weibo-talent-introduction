## 代码证据与设计结论

[完整代码证据附件](reply-snippet-variants-evidence.md)保留命令、命中行号、关键原文及哈希。依据为当前本地工作树；未把本地代码声称为刚核验过的生产版本。

1. **现有变体不是逐引用独立随机。** ContentVariantService:27 用 `(seed + ownerId) mod poolSize`。等长候选池相互联动；改为公共回复片段选择入口，每个引用各抽一次。允许重复，不承诺随机等于不重复。
2. **主题尚未引用片段。** MailComposeTemplateService:266 直接渲染 template.subject；create:72/update:98 将旧 subjectVariants 清空。不能把历史列的存在说成可用功能。新主题以片段 ID 为权威，名称仅用于显示。
3. **界面挤在左半边有布局依据。** replySnippetForm 是两列 form-grid，变体却用只在另一容器生效的 full-width。前端改为 span-2，并把原文和变体合并成一个可见编辑位置。
4. **不能只改编辑页预览。** 专家详情 app.js:11181 仍用 ORCID hash 作为 variantIndex；两类 preview-draft 都要带主题 ID 并改为新样本。
5. **生成后的同一邮件不重抽；重新跑批量任务是新生成。** ManualInitialOutreachService:700 每次 compose，:751 将同一 mail 交 SMTP；现有 PREPARED 写入没有冻结正文。跨任务重试固定旧正文需要另一个需求，本计划不擅自引入。
6. **既有 AI/RAG 框架不是本期模板引用接口。** ReplySnippetService:53 的注释明确框架只读原文，frameVersion 绑定原文。保持其行为；将随机能力下沉到现有 ContentVariantService，模板主题/正文及未来采用该引用能力的入口共用。

## 执行边界

- 用户手动新建各段回复片段，本期不拆分生产“项目介绍模板”、不代填十份文案。
- 片段编辑器只显示一个正文框，左右切换原文及变体；后台仍保存原文 + variants 数组。
- 主题只有一个可输入下拉框，以唯一选项标签/ID识别引用，其他文字为自定义；`{}` 图标与输入同一行。
- 预览提示“随机样本，发送时重新生成”，不承诺预览和未来正式发送逐字相同。
- 不修改 SMTP、退订、名单、批量节奏、AI 框架、QA 路由；不声称文本变体能保证进入收件箱。
- 本轮仅新增计划/证据，按 create-p 更新知识。未执行本文实施步骤、未发信、未部署、未提交代码。
