# 10,686 条历史待确认数据处置方案

状态：供审阅的数据处理方案，未执行回源核验、业务修改或发信。范围采用 2026-10-13 已读取的固定 ID 快照；本轮没有重新读取生产数据。代码前置见 [身份恢复方案](discovery-identity-recovery-master.md) 和 [准入放宽方案](discovery-admission-relaxation.md)。

## 需求描述

对固定名单逐人给出“保留可用、修复后使用、归档待证、明确排除”的处置结论、依据和实际动作。全量核验不能被抽样替代；抽样仅用于先发现解析问题。核验完成后不再把所有人混在一个无原因的待确认名单中。

本方案中“可用”指档案身份与准入可使用，不等于这次一定可发信。是否已联系、退订/抑制、邮箱状态、发送任务类型和地区条件另列，不能用修复绕过。

保持：真实业务 ID、历史邮件原文及关联、已有联系人/邮箱别名/附件/人工资料、人工决定、已确认真实字段。范围外：本轮物理删除档案、自动批量发信、把证据不足当作虚假专家、为了准入伪造方向或机构。

## 关键不变量

### Invariant I-1：一个固定 ID 一条主结论
- Rule：固定名单共 10,686 个真实 `_id`，三层副本合并计数。每人恰有一个主处置类别，允许多个原因和保护标志；状态变化保留历史，不能跨表重复计人。身份和来源事实采用核验时快照，不直接沿用旧原因。
- Applies to：名单、核验、清理清单、最终报告。
- Violation consequence：有人漏处理或人数虚增。
- 来源：本轮名单一致性检查。

### Invariant I-2：证据不足与明确错误分开
- Rule：没有 proof、缺方向/国家/机构、公开主页不展示邮箱、一次 403/超时均不能作为删除或假身份依据。只有同一来源的明确姓名—邮箱对应关系才用于新自动补证；历史认可单独注明授权依据，不升级为来源证据。
- Applies to：逐人分类、修复提案、归档与排除。
- Violation consequence：误清理真实专家，或把人工授权误当论文证据。
- 来源：现有历史审计、DiscoveryIdentity。

### Invariant I-3：修身份同时审计关联画像
- Rule：若姓名/作者编号原来绑错，不能只改姓名而保留旧人的 hIndex、论文、研究方向和分类。仅清理已证实归属错误的字段，逐字段列旧值、归属依据、新值/清空原因；来源不足但未证实错误的字段标待核，不无差别清空。再按正确作者重建可验证字段并重算分类/准入。
- Applies to：身份纠错清单、学术重建、人工复核。
- Violation consequence：称呼修正后仍用另一人的研究经历发信。
- 来源：9 月 27 日身份修复经验；K-enrichment-write-three-layers。

### Invariant I-4：历史关系、人工决定及并发保护
- Rule：按 docId、业务 orcidId、规范邮箱及邮箱别名检查已有联系人；有 APPLICATION、人工资料、历史邮件、人工准入决定者打保护标志。已有邮件不改内容、不换归属；同邮箱不等于同一人。字段更新按真实 ID 和版本条件，跨层部分失败不能报整体成功。
- Rule：已有 HOLD/REJECTED 保持；34 条既有历史认可继续单列。新证据与人工/历史认可矛盾时列人工复核提案，不暗改授权、也不将矛盾记录列为新自动可用。
- Applies to：预览、应用、重复处理、恢复报告。
- Violation consequence：损坏旧会话、绕人工决定或误合并共享邮箱。
- 来源：ExpertEmailAliasService、既有准入 identity_hash/revision。

### Invariant I-5：清理先限制用途，不物理删除
- Rule：本轮“清理”明确为首发隔离、范围排除、错误字段修复或重复记录禁重复首发。保留 RAW 和历史关联；不能只删标签或候选副本，因为 NEW 重试联系人也有发送入口。通过现有准入/抑制机制及统一 selector 验证隔离效果。归档待证不伪装成人才不合格。
- Applies to：处置应用、候选投影、发送预估。
- Violation consequence：页面看似清理了，其他入口仍发送；或永久丢失可恢复资料。
- 来源：BatchRecipientSelectionService、K-batch-send-filter-retry-parity。

## 实现方案

### 1. 冻结名单与备份

I-1/I-4：以已保存 10,686 ID 为本批范围，执行时重新读取每人已有三层、当前准入版本、邮箱验证/抑制、联系人/别名及历史关系。发现新增/删除/身份变化单列，不能悄悄替换名单。保存快照和版本、记录本批规则版本；备份成功才进入应用。

### 2. 全量只读核验，先处理最可能恢复的记录

I-1/I-2/I-4：先做 200 人分层回放验证工具，再逐条处理全部剩余 10,637 人；不能把样本比例当最终人数。

1. **5,541 条来源可得但关系未解析**：优先用当前解析器重新读取原论文。区分“同名缺证”“缺名但来源明确”“明确错绑”“原文仍歧义”。
2. **1,533 条 arXiv 注释歧义**：核对同篇 PDF 的作者脚注/通讯信息；HTML 注释挂在谁下面不能作归属依据。可用原文明确关系恢复，不能按列表顺序配人。
3. **3,560 条缺独立证据**：按已有 DOI/PMCID/ORCID/原项目编号回源；论文、公开作者档案、原项目官方联系人各走对应证据口径。公开 ORCID 无邮箱不判错误；历史项目联系人不能证明当前任职。
4. **2 条论文引用冲突 + 1 条姓名变体**：单独逐条人工核实；不走批量猜配。

每人安排两轮来源检查：第一轮原始来源，第二轮已有公开备用来源或来源恢复后的复查；沿原请求预算，429/预算暂停记 DEFERRED。达到本批核验预算仍无足够证据者关闭为“归档待证”，记录实际访问结果；不会一直自动重试。数据库/ES/报告写入故障属于未完成工作，不能用“无证据”掩盖。

SBIR、无论文 ID、已有人工资料者不能被论文恢复 API 强行处理；用现有原项目/公开档案证据核验，仍无法证明则归档。当前代码计划 02 不支持的来源或改名场景，只输出明确处置提案；不能借本方案授权执行代码范围外的补丁。

### 3. 逐人产生四类处置提案

I-1/I-2/I-3/I-4/I-5：按以下规则判断；缺方向/国家/机构本身不决定淘汰。

|类别|判断条件|历史数据动作|首发用途|
|---|---|---|---|
|A 保留可用|当前身份有可靠证据，或有仍有效的历史授权；无明确硬阻断、无相反新证据|保留事实，按既有准入/新政策形成持久结论|再按邮箱状态、历史联系及本次任务条件筛选|
|B 修复后可用|原文已明确正确关系，但库内缺证、缺名，或存在可纠正错绑|先给出字段差异；安全补证/纯缺名走代码前置方案；错绑及有历史关系者走逐条审阅纠错，重建学术归属并重算|修复、回读、准入全部完成后才转 A；B 本身不是可发送状态|
|C 归档待证|两轮后仍无独立归属、来源不可得、共享邮箱歧义，或人工暂缓|保留原始事实与原因，退出本轮可发送清单；待有新证据或明确人工决定才重开|本轮自动首发隔离；不自动物理删除|
|D 明确排除/清理|可靠身份下明确不属目标、确认不可用邮箱、确认的重复副本、人工拒绝，或无法安全纠正的确认错绑|按下面的细分动作处理，不能统一删除|在适用范围内排除，保留历史业务关系|

优先级：已有人工 HOLD/REJECTED 单列保护；新明确冲突不能进入 A；身份先于其衍生研究分类。未经身份核验的旧 OUT_OF_SCOPE 可能来自错绑画像，先检查归属，不能当作永久排除依据。既有人工认可与新负面事实矛盾者须逐条审阅，不自动撤销授权。

### 4. 把“清理”落成具体动作

I-3/I-4/I-5：

|情况|应做|保留|
|---|---|---|
|姓名/作者编号确实错绑|对未关联历史关系的记录提出更正；有历史关系者逐条审阅；清除/替换已证实属于他人的学术字段，重算分类|真实业务 ID、邮箱、原始证据和备份；历史邮件内容/关联不改|
|邮箱确认不可用或已有退订/抑制|复用原邮箱限制及准入机制隔离首发；临时失败/catch-all/未知不能冒充永久无效|专家事实与联系历史，已有人工规则|
|身份可靠但明确不属本次目标|按目标范围排除，保留档案；不因行业不同判作垃圾数据|身份、经历、历史沟通|
|多个 ID 确认属于同人同邮箱|提出主记录与重复副本关系，阻止重复首发；不同 ID 有联系人/邮件时只隔离重复发送，不自动合并迁移历史|既有 ID 和历史引用；共享邮箱/证据冲突不合并|
|缺证据而无法确认|归档待证，记录原始来源和失败原因|原始记录，等待新证据的恢复入口|

无一类仅凭本次初分达到物理删除依据。若以后确需物理删除，应另列“无任何历史引用、已备份、确认为噪声或重复”的具体 ID 清单；不包含在这次方案应用范围内。

### 5. 先交名单，再受控应用

I-1/I-3/I-4/I-5：先交完整 A/B/C/D 提案及逐字段清理清单。后续获得实施授权后，先 50 条小批，再按结果扩大；同一 ID 三层采用条件更新，失败可继续，不新增第二套档案。A 写准入，B 修复成功再转 A，C/D 通过既有审核/准入及邮箱机制形成实际限制，不能只改标签。

C 的“归档待证”是报告/运营处置概念，不新增 admission 枚举；对本批授权范围内可经既有审核流程明确 HOLD，保留具体原因。D 的人工 REJECTED 或邮箱限制同样走真实操作者的既有流程，不伪造人工确认。已有人工/历史结论保留；需改变者单独列出供审阅。

代码方案 02 有意禁止覆盖已填姓名、清学术污染和改联系人，因此此类 B 项的事实纠错必须先完成逐条证据与补丁设计，再作为有限名单的独立维护批次；不能把前置方案的“自动跳过”误报为已清理。批次关闭时，未获准或未解决的 B 项移到 C，记录待修原因与提案；执行失败仍单列，不能算完成。

### 6. 交付结果与关闭条件

I-1/I-5：最终交付以下材料，不只给汇总数：

1. **完整逐人结果**：10,686 ID 全覆盖，姓名/邮箱当前值、出处/时间、最终处置、依据、保护标志及处理回执。
2. **可用清单**：区分原有可用、修复恢复、历史授权例外；另列本次实际预估可首发名单及排除原因。
3. **清理清单**：每人明确“仅隔离/范围排除/更正身份/清理错误字段/重复发送隔离”，附前后差异；不使用笼统“清理完成”。
4. **归档清单**：每人说明缺哪条证据、尝试过什么、什么条件下可恢复；不继续混成日常活跃待审。
5. **核验报告**：三层回读、人工决定保护、联系人/别名/历史邮件未损坏、预估入口一致、失败与回滚提案。

正常完成时 B 临时状态归零，只有 A/C/D 三类最终处置且人数相加等于固定名单总数；A 中另统计“经修复恢复人数”，不得重复相加。若出现执行失败或未读取成功的档案，本批明确为“未完成”，单列对应 ID。
