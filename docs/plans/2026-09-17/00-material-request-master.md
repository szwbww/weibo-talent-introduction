# 材料索取主计划（约束 01 → 02 → 03）

本文件是三份子计划的跨计划约束与整体验收门槛，不是第四份开发任务。实施细节、逐文件范围和各自验收，以子计划为准：

1. [01：静态资源缓存测试夹具](01-material-request-cache-fixtures.md)——先解除测试对旧缓存键的硬编码。
2. [02：独立五项状态接口](02-material-request-status-api.md)——提供材料索取目录、三态持久化和英文正文。
3. [03：操作栏与富文本弹窗](03-material-request-ui.md)——消费 02 的接口，完成选择、预览、确认填入。

执行顺序：01、02 分别验证后，才执行 03；02 可以独立于 01 开发，但 03 的缓存键更新必须等 01 完成。三份计划各自独立验证，最后再做本文件的跨计划验收。任何子计划的接口、状态语义、文件范围或样式契约发生变化，先修订本文件及受影响子计划，再继续实施；不得在执行时口头扩范围。

## 需求描述

- 可观察结果：专家联系操作栏保留手动三态材料标签；人工回复富文本工具栏新增「材料索取」，打开后按专家状态选择需要的五项，预览并确认，将固定英文引言和项目符号列表追加到当前草稿，由用户继续手动修改、发送。
- 必须保持：旧七项材料状态与 `${pendingExpertMaterials}` 变量、RAG 对旧 `CV` 的判断、专家上传资料分页、会议确认及附件、人工回复原正文和手动发送路径。
- 不做：自动识别上传文件、旧七项与新五项状态自动映射、修改邮件模板或旧变量、确认时发送邮件、改写上传文件 API、生产部署。主计划本身不授权修改业务代码。

## 关键不变量

### Invariant I-1：五项请求目录独立于旧七项
- Rule：新目录顺序固定为 `REQ_PUBLICATIONS`、`REQ_PROJECTS`、`REQ_PATENTS`、`REQ_AWARDS`、`REQ_DEGREES`；对应页面短标签和英文正文以 02 的服务端目录为唯一来源。旧七项、旧变量和 `CV` 读取不变；两个目录不得互相推断状态。
- Applies to：02 的迁移、服务和 API；03 的操作栏与弹窗读取。
- Violation consequence：材料语义错配，旧变量或 RAG 行为被误改。
- 来源：original；02 的 I-1/I-3。

### Invariant I-2：三态与确认边界
- Rule：缺行表示 `PENDING`；`PROVIDED`、`DECLINED` 持久化；改回 `PENDING` 删除行。弹窗只允许选择 `PENDING`，另外两态禁选且不进入拼接结果。确认只追加到当前人工富文本草稿，不改状态、不发送邮件；取消不写草稿。
- Applies to：02 的状态 PUT/GET；03 的选择、预览和草稿写入。
- Violation consequence：已提供或暂不愿提供的材料被索要，或确认造成意外发送/状态变更。
- 来源：original；02 的 I-2；03 的 I-2/I-3。

### Invariant I-3：接口边界与文件列表隔离
- Rule：新状态接口仅使用 `/api/expert-contacts/{contactId}/material-requests` 及 `/{code}`；现有 `GET /api/expert-contacts/{contactId}/materials` 始终表示上传文件分页，不复用为状态数组。03 必须消费 02 的新接口形状 `[{code,label,status,requestText}]`。
- Applies to：02 的路由；03 的两个读取点和状态写入点。
- Violation consequence：路由冲突，专家上传资料或操作栏显示失效。
- 来源：02 的 I-4；`ExpertMaterialController.kt:27-45`。

### Invariant I-4：内容及对象隔离
- Rule：拼接结果严格采用用户给出的固定引言 `To proceed, please provide the following supporting materials:`，其后仅为本次选中项的英文无编号项目符号，顺序与服务端目录一致；文本作为文本节点插入，不解释为 HTML。异步响应和确认必须核对当前专家、来信和草稿版本，不得写入已切换的回复。
- Applies to：02 的 `requestText`；03 的弹窗预览、确认与草稿恢复。
- Violation consequence：内容漂移、XSS、跨专家串写或覆盖既有正文。
- 来源：original；03 的 I-2/I-3/I-4。

### Invariant I-5：发布时的缓存键一致性
- Rule：03 更新静态资源缓存键前，01 必须把测试夹具改为从 `index.html` 读取实际键；发布时 `index.html` 的 11 个资源引用使用同一个新键，资源列表及顺序不变。
- Applies to：01 的九份 JS 测试；03 的 `index.html`。
- Violation consequence：旧资源缓存导致前后端不匹配，或测试因硬编码旧键失败。
- 来源：01 的 I-1/I-2；03 的 I-5。

## 现状审计

- 状态存储：`V111__create_expert_material_status.sql:7-20` 限定旧七项代码、存储态仅 `PROVIDED/DECLINED` 和 `(expert_contact_id, material_code)` 唯一键；`ExpertMaterialService.kt:70-138` 负责旧七项读写及待提供变量组装。02 已列出该表全部迁移、写路径和读路径；本主计划不新增任何写路径。
- 旧消费者：`MailVariableService.kt:158,274-277` 注入 `${pendingExpertMaterials}`；`RagProcessContextResolver.kt:31-49` 读取旧 `CV`。新旧状态隔离是跨模块验收点（I-1）。
- HTTP：`ExpertContactManagementController.kt:243-253` 留有旧状态 PUT；`ExpertMaterialController.kt:27-45` 占用 `/materials` GET 作为分页上传文件接口。新状态路由必须独立（I-3）。
- 前端读取/写入：`app.js:8055-8063,8124` 的材料行仍按数组响应渲染；`mailbox-chat.js:2834-2887` 生成现有会议确认工具栏，`:3758-3830` 保存人工草稿，`:4440-4485` 处理会议弹窗。03 的 S-1/S-2 样式契约和逐字 DOM/CSS 基线是前端唯一授权样式范围；本主计划没有前端文件变更。
- 静态缓存：`index.html:11-15,2110-2115` 有 11 个同键资源引用；01 已审计九个对旧键有依赖的 JS 测试。01 的改造结果由 03 的缓存键变更消费（I-5）。
- 交互点：02 新 PUT → 新 GET → 03 操作栏/弹窗；02 旧状态保留 → 旧变量/RAG；03 弹窗确认 → 人工草稿重挂载/发送；01 测试夹具 → 03 缓存键更新。上述四条均须在整体验收中覆盖。

## 人工验收清单

### A-1：三态经接口传到两个界面
- 前置条件：测试环境已执行 02 迁移并部署 03；选择有真实来信的专家，五项初始未设置。
- 操作步骤：1. 在专家联系操作栏将「专利」设为「已提供」、「荣誉奖项」设为「暂不愿提供」；2. 刷新；3. 打开该来信的人工回复「材料索取」。
- 预期结果：操作栏五项仍按代表性论文、科研项目、专利、荣誉奖项、学位排列；专利已提供、荣誉奖项置灰；弹窗这两项禁选，另外三项默认勾选。
- 覆盖：I-1、I-2、I-3；新 PUT → 新 GET → 两个界面。

### A-2：英文材料请求只填草稿
- 前置条件：沿用 A-1，富文本已有 `Dear Professor,`。
- 操作步骤：1. 在材料弹窗确认默认三项；2. 检查富文本；3. 手动删除一条项目符号，再切换页面并返回。
- 预期结果：原文保留；追加固定英文引言和三条无编号英文 bullet，顺序为论文、项目、学位，文字与 02 五条目录中对应项逐字一致；删改后的草稿恢复；邮件未发送，材料状态未变化，无额外成功提示。
- 覆盖：I-2、I-4；状态读取 → 预览 → 草稿写入/重读。

### A-3：旧业务及目标隔离回归
- 前置条件：专家 A 有 `CV=PROVIDED`、已上传文件及含会议确认/ICS 的未发送回复；专家 B 也有来信。
- 操作步骤：1. A 打开材料弹窗后取消并切到 B；2. 检查 B 的草稿；3. 返回 A 查看原草稿、会议块和上传文件；4. 预览含 `${pendingExpertMaterials}` 的原模板；5. 按原方式人工发送一封测试回复。
- 预期结果：B 不出现 A 的材料段；A 的会议正文、ICS 与上传资料分页仍在；旧变量仍输出旧七项目录而非新五项；人工发送仍需点击原发送按钮。旧 `CV` 的 RAG `RECEIVED` 判定以 02 的自动化回归确证。
- 覆盖：I-1、I-2、I-3、I-4；旧变量/RAG、上传分页、会议与发送路径。

### A-4：资源缓存与界面目测
