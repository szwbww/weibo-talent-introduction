# user1 授权专家邮件只读：开发总计划

状态：**待用户审阅；尚未实施**。日期：2026-10-27。入口：[代码审计](user1-mail-audit.md)。使用 create-p；本轮只写计划、证据与知识记录。

## 需求描述

内置 `user1 / qfuser1`。登录后只显示“收发件箱”业务 tab，只能查看 admin 授权专家的收件/发件正文；不允许发送、修改或查看/下载附件。admin 在对应专家的会话头部授予/撤销 user1 的查看权，不建设用户管理页面。

必须保持：admin 的登录/改密、原有导航、邮件阅读/回复/附件/草稿行为；定时收发信与任务后台流程。本次不做泛化 RBAC、多账号配置页、发送权限、附件权限开关、授权批量导入、实时推送撤销、翻译/备注/材料功能。

授权粒度明确为 **user1 × expert_contact.id**，专家在所有真实发件邮箱下的历史及未来往来均适用；不按单封信/邮箱分别授权。默认无授权，即空列表。以上为本次设计决定，不声称已有实现。

## 关键不变量

### Invariant I-1: 权限由 session 与数据库决定
- Rule: 登录最终只接受精确 admin/user1；user1 的业务 API 默认拒绝，仅放行会话列表、获授权专家的时间线；不信任前端隐藏、query username 或客户端 role。
- Applies to: 登录、me、拦截器、grant 写读、会话 SQL、详情准入。
- Violation consequence: 直调接口绕过界面获得邮件/附件或执行发送。
- 来源: original。

### Invariant I-2: 无 grant 即无正文
- Rule: grant 行存在才可读；不存在/撤销即拒绝。列表总数与页数据均在 SQL 层应用同一 EXISTS，详情每次请求重新查权。撤销提交后开始的新请求不再获得正文；已准入的在途请求可能完成，已看过的数据不承诺远程抹除。
- Applies to: grant PUT/DELETE、count/page、首次/更早页读取、刷新及窗口恢复。
- Violation consequence: 默认全开放、空洞分页、撤销后仍从缓存回显。
- 来源: original；K-mailbox-draft-cache-owner-capture。

### Invariant I-3: reader 没有发送及附件能力
- Rule: reader 仅正文/必要会话信息；所有发信、草稿、附件及其他业务接口拒绝。时间线附件数组为空、日历=null、附件计数=0；reader 不渲染操作工具。
- Applies to: 拦截器、DTO 投影、只读渲染器。
- Violation consequence: 隐藏下载按钮但仍暴露附件入口或自动保存草稿。
- 来源: original。

### Invariant I-4: admin 与后台不回归
- Rule: 只在精确 user1 的 HTTP 请求应用限制，不重写现有发件/收信服务；admin 原有路径不改语义；邮箱范围继续包括 disabled 历史邮箱并排除 SIMULATOR_NOOP。
- Applies to: 条件分支、会话查询、前端宿主分流。
- Violation consequence: 用户权限误影响自动回复/任务或管理员历史邮件。
- 来源: K-sender-account-enabled-scope。

### Invariant I-5: 分步可核验、最终才开放账号
- Rule: 01→02→03→04→05 严格顺序。前四步保留 admin-only 登录，05 最后增加 user1 bootstrap 并开放登录。每步独立机器验证，最终合并验证及人工验收后才交付上线。
- Applies to: 所有子计划；AuthController/index 共享文件。
- Violation consequence: 新账号先开放，SQL/UI 权限尚未完成；共享文件互相覆盖。
- 来源: K-master-plan-shared-file-sequential-gates。

## 现状审计

完整证据见 [审计附件](user1-mail-audit.md)。关键结论不是猜测：AuthController:31 硬编码 admin；AuthInterceptor 只有登录/首改密码校验；ConversationController.messages 不接收 session；Repository.expertPredicates 为 count/page 共同插入点；附件分散于多个 Controller；现有 chat 选择专家会读取备注、草稿、位置、附件，不能直接把按钮藏起来。

范围只涉及认证/授权、邮件查询、前端宿主与只读渲染。新存储只有 `expert_mail_read_access`；现有数据库表、ES mapping 不加字段。认证只增加一个派生响应字段 `mailReadOnly`，不落库。

执行前检查（I-5）：

1. 对照证据中的工作区 SHA 与 dirty 清单，保留现有用户变更；不 reset，不覆盖 application.yml/CLAUDE 等已有修改。
2. 核对当前迁移最大编号，本次为 V165；01 拟用 V166，若已占用，先更新01清单及证据再执行。
3. 核对测试 MySQL 是独立库、认证开关 true、线上源码版本与本地差异；这些当前未实证，不准写成已验证。
4. 每步执行→机器验证；共享文件串行。01–04 可记录 `IMPLEMENTED_NOT_RELEASABLE_FOR_USER1`，不是整个功能完成。
5. 最终检查真实登录、授权/撤销、直接 URL 越权、管理员回归。上线不在本次计划创建授权范围。

回滚：优先退回已完成 04 的版本，重新禁止 user1 登录并使现有 session 失效；保留 grant 表/记录，禁止删表破坏授权数据。若退到 01 之前版本，旧拦截器可能接受已有 user1 session，必须先失效全部 session 并禁用 user1 账号，不能仅回滚 jar。此为发布操作规范，不在本轮执行。

复杂度判断：**中等**。账号创建本身很小，实质工作集中在 SQL 分页前授权、详情直连防绕过、附件旁路和前端生命周期。采用单表、固定用户、独立只读模块，不引入角色系统。未提供伪精确工时；机器/数据库条件及线上代码差异未核实。

## 验收标准

- I-1：真实 MVC 映射测试覆盖 allowlist、mapped denylist、匿名401；精确 session 身份；非 admin 授权写403。
- I-2：真实 MySQL 空授权/交错授权分页/搜索/账号筛选/撤销；不以 mock 代替 SQL；前端切专家与失权清空。
- I-3：已知所有附件通道及发信/草稿通道403；正文响应不含附件对象/URL；浏览器网络清单仅允许必要读请求和 auth。
- I-4：admin 登录改密、原聊天/草稿/附件及后台自动任务回归；既有 JS/Maven 测试通过。
- I-5：五份子计划均有机器验证结果；MySQL IT 必须是实际执行通过，不能 skipped；完整最终验证后再执行下面人工清单。人工开始时才导出 `user1-mail-master-acceptance.md`。

## 人工验收清单

### A-1: 从零授权到可读
- 前置条件: 隔离测试环境、认证 true、完成五步；两名有收发历史的专家 A/B，user1 无 grant。
- 操作步骤: 1. user1/qfuser1 登录。2. 查看菜单和空列表。3. 另一个浏览器用 admin 为 A 授权。4. user1 刷新并打开 A。
- 预期结果: 仅“收发件箱”业务 tab；初始“暂无已授权的专家邮件”；授权后仅 A，收/发正文可读，B 不出现。
- 覆盖: I-1/I-2/I-5；需求全部基本闭环。

### A-2: 越权、附件与撤销
- 前置条件: A 已授权且存在来件、已发通用附件、日历附件；B 未授权；admin 能提供其真实接口地址。
- 操作步骤: 1. user1 直接 GET B/messages 和各附件地址。2. 用 user1 请求真实发送/草稿接口。3. admin 撤销 A。4. user1 刷新、翻更早页、切出再切回窗口。
- 预期结果: 未授权详情及所有受保护附件/写接口403；撤销后的新详情请求403；当前视图不再显示旧正文并提示“暂无权限查看该专家邮件”；列表刷新后无 A。
- 覆盖: I-1/I-2/I-3。

### A-3: 管理员与任务回归
- 前置条件: 测试管理员、测试收件箱、可发往受控邮箱的任务；同时存在 enabled=false 的历史邮箱邮件。
- 操作步骤: 1. admin 登录并逐项打开原 tab。2. 阅读/下载附件、编辑保存草稿并向受控邮箱发信。3. 运行一次既有收信/自动回复或受控任务。4. 查看停用邮箱历史会话。
- 预期结果: 原 tab 均可见；草稿保存、发送成功并产生原有记录；附件字节可下载；任务状态与本次改动前相同；历史邮件保留。
- 覆盖: I-4；必须不变的各项。

### A-4: 真实前端与身份切换
- 前置条件: 1440px 桌面、390px 手机；admin/user1 均可登录。
- 操作步骤: 1. admin 登出后 user1 登录，再反向切换。2. 刷新页面。3. 对照03样式契约核对列表和收/发气泡。4. 检查手机菜单及网络记录。
- 预期结果: 不串用前一账号正文/草稿；user1 手机下拉仅“收发件箱”；桌面左栏306px、气泡最终字号13px/行高1.55，390px上下排列；无待处理/草稿/材料/发送入口及额外业务请求。
- 覆盖: I-3/I-4/I-5；03 S-1/S-2/S-3，04 S-1。
