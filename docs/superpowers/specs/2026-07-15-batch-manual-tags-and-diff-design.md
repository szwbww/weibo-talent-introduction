# 批量邮件手动执行标签与差异状态设计

## 目标

- 手动执行未关联定时任务时，不展示配置差异红框、已修改标识和原值。
- 定时任务编辑与手动执行的标签字段改为可搜索多选下拉框。
- 保持现有后端 `tags: string[]` 请求结构不变。

## 状态规则

- 只有 `manualSource` 指向已选择定时配置时，才计算和展示字段差异。
- 用户修改任务搜索词，使其不再等于当前来源任务名称时，立即解除来源关联并清除来源 ID、更新时间及全部差异标识。
- 解除关联时保留当前手动表单参数，后续执行视为独立手动执行。
- 点击“清除选择”仍恢复独立手动执行默认参数。
- 从任务列表点击“手动”或在下拉框选择任务时，继续带入完整配置并启用差异提示。

## 标签选择器

- 定时编辑和手动执行各使用一个共用行为的可搜索多选组件。
- 输入框用于筛选候选标签；下拉列表使用复选状态；已选标签显示为可删除 Chip。
- 候选标签合并 CANDIDATE 与 APPLICATION 的标签聚合结果，按名称去重。
- 配置中已有、但聚合结果中不存在的历史或自定义标签必须保留并可取消选择。
- 空选择提交空数组；标签顺序不参与手动配置差异判断。

## 数据与错误处理

- 打开批量任务控制台时异步预加载两层标签聚合结果。
- 任一聚合请求失败时保留另一请求的结果；全部失败时组件仍显示当前配置已有标签。
- 搜索仅在前端过滤已加载候选项，不新增接口、不影响任务配置接口。

## 验收

- 未选任务时修改漏斗、标签或限额，任何字段均无红框。
- 清空已选任务搜索词后，来源摘要变为独立执行，红框立即消失，当前参数保留。
- 两个标签字段均可搜索、多选、删除，保存或执行请求仍发送字符串数组。
- 选择定时配置后修改标签，标签字段正确标红，确认弹窗展示标签变更。
