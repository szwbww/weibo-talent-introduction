# ContactOut 已显示邮箱采集

本地 Chromium 扩展（Manifest V3），供 Dia / Chrome 使用。点击一次采集当前已加载页面；每个人一条记录，所有已经显示完整地址的邮箱都保存。只剩 `***@…` 的资料卡不导出，混合资料卡仅保留完整地址。

## 安装

1. 解压 `contactout-visible-export-1.5.6.zip`，保留解压后的目录。
2. 在 Dia 地址栏输入 `chrome://extensions`（若被改写为浏览器自己的扩展地址，继续使用该页面）。
3. 开启「开发者模式」，点击「加载已解压的扩展」。
4. 选择包含 `manifest.json` 的 `contactout-visible-export` 文件夹。
5. 从浏览器的扩展菜单打开「ContactOut 已显示邮箱采集」，可将图标固定到工具栏。

## 自动联网企业评分（1.5.6）

以后不用给每家企业手写JSON。插件弹窗打开时会读取 ContactOut 的 Company 筛选、联网核查企业、显示来源和各项分数、自动标记当前页；无需启动终端或本机服务。切换企业会重查；同一家缓存30天，跨年/规则升级自动失效。未能读取筛选时，在“当前企业”填写全名后查询；每次最多5家。

首次使用：展开默认收起的“自动企业评分”，填写 DeepSeek API Key 和 Tavily API Key，勾选自动评分，点击“保存直连配置”。Tavily 只负责检索公开网页，DeepSeek 只根据检索片段提取事实 JSON；无来源或证据不匹配会返回“待核实”，不会让模型按常识补分。DeepSeek 的普通 Responses API 会忽略 `web_search`，因此仍需要 Tavily 提供可核验证据；官方说明见 [DeepSeek Responses API](https://api-docs.deepseek.com/guides/responses_api/) 与 [Tavily Search](https://docs.tavily.com/documentation/api-reference/endpoint/search)。

两个密钥以**本机明文**形式保存在 Dia 扩展的 `chrome.storage.local` 中；任何可访问该浏览器配置的本机用户或扩展调试工具都可能读取它们。密钥不会发送给 ContactOut、不会写入导出文件，扩展只获得 `api.deepseek.com` 和 `api.tavily.com` 的联网权限。不要在共享电脑使用，密钥泄露时请立即在对应平台撤销。

以后：在 ContactOut 选择企业 → 打开插件 → 自动查询和标记。弹窗关闭期间不检测新企业；查询时请保持弹窗打开。手动“重新联网查询”可强制刷新；限流和网络失败不会循环重试。新模式使用已保存v3岗位规则；仍为v1/v2时仅本轮使用默认v3，不覆盖旧规则。

通用分数由程序计算：

| 项目 | 分值 |
|---|---|
| 总部属于IMF发达经济体／其他经济体 | 20／10 |
| 半导体、AI、软件、生物制药、量子产业 | 20（统一产业分类分，非实际薪酬） |
| 先进材料、自动化、航空航天 | 10 |
| 明确其他产业 | 0 |
| 集成电路、AI、量子、生物科技中图片列明的具体紧缺方向 | 60 |
| 仅能证实属于上述四大领域 | 40 |
| 明确非重点产业 | 0 |

按本次公司实际业务，不把母公司/其他事业部的产业标签和五百强身份直接套给子公司。世界五百强需 Fortune 官方近年度名单的明确入榜证据，明确入榜直接100分、L1；此时其他评分项不参与计算。**未证实世界五百强（包括无相关来源、null 或未提供字段）默认按非五百强的五百强项0分继续计算，并在结果中标为“低置信”**。国家、产业或重点方向证据不足仍是“待核实”，不会强行评分。非五百强80–100分L2、60–79分L3、其余L4。评分是模型辅助事实整理，来源可点击复核。

新联网结果在独立本地缓存保存，旧手动企业JSON继续保留；自动模式只消费有效联网结果，不沿用之前批量设置的九家100分。关闭自动评分并保存可恢复手动企业库。已有邮箱名单、规则导入/导出、清空专家功能不变。缓存只保存企业资料，不上传专家名字/邮箱/履历。

升级：先导出名单作备份，将1.5.6文件覆盖**原扩展目录**后重新加载；勿卸载。首次启用需填写两项 API Key。1.5.3及以前的联网缓存和本机连接码会自动失效并重新核查；专家名单和手动企业配置不受影响。

## 每次使用

1. 在 ContactOut 搜索结果中手动点击 `View email`。
2. 打开扩展，点「采集当前页已显示邮箱」。插件自动点击已显示完整邮箱资料卡的 `more / Show more`，等待内容展开后采集。请保持弹窗打开至完成；界面显示自动展开人数、本次读取数、本地累计人数和邮箱数。已展开的资料不会折叠，只有掩码邮箱的资料卡不会展开。若提示展开失败，请手动展开对应资料后再次采集。
3. 翻页前采集一次；翻页、滚动加载或继续显示邮箱后，可再次采集。
4. 点「导出 CSV」或「导出 JSON」，检查浏览器下载列表。导出包括本地累计的全部记录。

不需要选择主邮箱。个人邮箱、工作邮箱、学校邮箱全部保留，后续再识别。重复采集同一人会合并邮箱（优先 LinkedIn 链接，否则姓名与公司）；识别信息不足时按资料原文匹配。同名同公司人员需要人工核对。扩展重装/清除浏览器数据可能丢失名单，请定期导出。

## 升级至 1.4.0

先导出名单 CSV/JSON 和已保存规则作备份。用新包文件更新**原扩展目录**，再在扩展管理页点「重新加载」；不要卸载扩展或换目录重新安装。专家和岗位规则存储键不变，企业评分使用独立新键；清除浏览器数据或重新安装仍可能丢失本地数据。

**已有 v1/v2 岗位规则不会自动替换**。启用企业分层：打开「编辑岗位与企业规则」→恢复默认岗位规则→保存；再导入已审核企业评分 JSON→保存。重新打开确认岗位 `schemaVersion: 3` 和企业数量，名单人数、邮箱数应保持不变。

## 企业评分分层（1.4.0）

点击「标记职级（红／黄）」。插件只使用已保存、人工审核并带来源的企业库，不联网猜测企业分数：

- 世界五百强：普通明确技术／研发岗 L1 即可。
- 非五百强 80–100 分：至少 L2（Senior/Sr + 技术词）。
- 非五百强 60–79 分：至少 L3（Staff/Principal/Lead/技术经理等）。
- 非五百强 0–59 分：至少 L4（Distinguished/Chief/技术总监等）。L4 明确技术岗即使企业未收录也保留。
- 红色边框：已知企业且技术职级低于门槛，或当前明确初级／非技术且无达标历史经历。
- 黄色边框：企业未收录、Associate/Assistant/Postdoc 等歧义、履历未展开或无法可靠解析。

页面只增加红／黄内描边，不插入说明文字、不覆盖资料卡底色，也不改变卡片布局。

每段任职只把该段公司与该段职称组合，不能把甲公司的五百强身份与乙公司的 Engineer 拼接。任一当前或历史任职独立达标即保留。企业只按规范化后的完整名称或显式别名匹配，不自动继承母子公司关系。

标记和自动企业评分会先顺序展开**当前已加载资料卡**的 `more / Show more`，再按完整履历核对；不需要显示邮箱。只点击资料卡内严格匹配的 more，不点击邮箱、电话、AI写信或其他按钮，不翻页、不请求 ContactOut 接口。展开失败的资料仍为待核实；联网评分模式下翻页、滚动加载或刷新页面后需重新分析。「取消标记」只清除红黄标记，不展开 more。

## 手动企业库自动分析（1.5.5）

关闭“自动企业评分”并保存后，岗位规则和企业评分库只需保存一次。重新加载扩展并刷新当前 ContactOut 标签页，首次结果加载、手动翻页或结果列表替换后，插件会自动展开当前已加载资料卡的 `more / Show more` 并重标。不会点击 `View email`、`View phone`、AI写信或分页，也不会采集邮箱。已评分当前企业的低职级结论优先于无关历史任职的未收录提示；例如 Henkel 30分/L4 的当前 R&D Scientist 会标红。启用联网评分后，手动自动分析会停止并清除旧手动标记，避免两套评分混用。

此功能只增加页面边框，不删除名单、不改变导出范围或邮箱。现有名单存储键保持不变。

「编辑岗位与企业规则」分别支持岗位和企业 JSON。导入／恢复只修改编辑框，显式保存才写入。专家名单、岗位配置、企业配置使用三个独立本地键；清空专家不会清除两类规则。企业记录必须含唯一 id、名称／别名、总部国家、发达经济体标记、五百强及年度、高薪产业分、重点产业分、核验日期和 http(s) 来源。非法或重复别名配置不会覆盖旧数据。

## 输出字段

导出后的邮箱分类、资格核对和线上发送条件仍需另行审核。本安装包仅包含浏览器扩展和使用文档，不包含导入或发送工具。

- `name` / `company` / `jobTitle` / `location`：从资料卡可见文字提取的辅助字段。
- `linkedin`：当前资料卡公开显示的个人链接（如果存在）。
- `emails`：CSV 用分号分隔；JSON 为数组。一个人所有完整邮箱都保留。
- `source` / `sourceUrl` / `capturedAt` / `firstCapturedAt`：来源和采集时间。
- `profileText`：资料卡可见原文，供后续核对。没有推测学历、研究方向、国籍或高级职务资格。
- `needsReview`：始终为 true，表示尚未核对发送/导入条件。

姓名、职位等字段不是资格认定，页面变化可能导致字段缺失；请以原文及实际履历核对。导出文件包含个人资料，保存在你的本机。

## 采集范围与限制

- 读取当前页面中已经渲染、未被隐藏的正文；不读取 HTML 属性中的隐藏邮箱、应用状态、接口或掩码背后的数据。
- 可采集已经加载但需要滚动才能看到的资料卡；尚未加载或已被虚拟列表移除的卡片，需要你手动滚动后再采集。
- 采集与分析只自动点击资料卡内的 `more / Show more`；分析会覆盖当前已加载的资料卡，采集只覆盖已显示完整邮箱的资料卡。两者都不点击 `View email`、`View phone`、AI写信或其他按钮，不自动翻页、调用 ContactOut API、发送邮件或写入 ES。
- 使用资料卡复选框结构匹配邮箱与专家。如果发现完整邮箱却无法可靠匹配资料卡，提示跳过数量，避免把多人的邮箱混在一起。
- 申请 `activeTab`、`scripting`、`storage`，以及仅限 `contactout.com` 的页面读取权限，用于保存一次后在该站结果刷新/翻页时自动分析。数据存储使用本机 local storage，无远程服务。
- 本工具不改变 ContactOut 的数据使用或导出授权范围。

## 验证

运行 `node tests/core.test.cjs` 测试邮箱过滤、字段解析、合并及 CSV 转义。
安装 Playwright 后运行 `node tests/browser.test.cjs`，或设置 `PLAYWRIGHT_MODULE` 为本机 Playwright 包路径。浏览器测试使用完全合成的 ContactOut 风格资料卡，不连接真实账号。

运行 `node tests/popup.test.cjs` 验证配置校验、导入／恢复暂存、保存后重新打开以及专家缓存保留；使用模拟浏览器存储。

真实 ContactOut 页面 DOM 和 Dia 安装需在你的浏览器首次加载后验证；页面改版可能需要调整采集器。异常时保留截图与采集提示即可，切勿提供登录凭据。
