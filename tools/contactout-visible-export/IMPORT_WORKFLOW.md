## 完善后的操作流程

1. **采集原始资料**：仍然保留全部完整邮箱，不在浏览器中选主邮箱。1.1.0 起点击采集会自动展开已显示完整邮箱资料卡的 `more`，保留可见职责、经历、学历和技能；若提示展开失败，请手动展开后重采。浏览器不保存 SSH 或 ES 凭据。
2. **本地预检**：识别个人/当前公司/学校/未知域名，保留原始邮箱列表；生成缺项、对标目录匹配和待审核报告。陌生自定义域名不自动当工作邮箱，也不自动丢弃。
3. **审核资格和技术方向**：核实当前职务、职责范围和对标企业；确认与国内目标企业技术需求的具体关联。有证据后才确定研发类型与英文研究方向。不通过或证据不足者保持待审核。
4. **验证并选择主邮箱**：对候选个人邮箱做可达性验证；保存验证来源、时间和状态。找到多个有效邮箱时仍只选一个主邮箱，其他作备用；不会把同一个人拆成多条发送记录。备选邮箱切换不能重置人员级联系历史。
5. **线上只读查重**：按全部邮箱、LinkedIn、姓名/公司检查 ES 和 MySQL 联系/发送/退订/退信状态。已有身份先人工合并，不能覆写原状态或用备用邮箱重复发介绍。
6. **准备 ES 导入预览**：`email` 仅放已选主邮箱；`researchFields` 放核实后的英文研究方向；`expertClassification.type` 来自真实分类；保留真实 ContactOut 来源、全部备用邮箱、原始资料和验证证据。新记录使用稳定人员 ID。未确认这些条件时不输出“可发送”结论。
7. **配置 ContactOut 专属任务**：建议专属标签 `ContactOut个人邮箱待发送`，先关闭自动发送；采用模板 1、候选层、未联系、已核实研发类型。这个配置尚未创建。不得为匹配现有任务，给 ContactOut 数据贴 `SBIR导入` 或 Apollo 已验证标签。
8. **导入后验收**：再次查重并复核任务配置，创建新文档而非无条件覆盖已有记录；检查实际候选命中数、被排除原因、每人一封及渲染后的英文邮件。最终发送由获授权的操作触发。

线上默认任务已经自动运行，所以“导入满足该任务条件的 ES 文档”可能触发后续定时发送；不能把这种导入当作单纯存档。

## 已提供的本地预检

`prepare_review.py` 读取 CSV 并输出 JSON 审核报告。当前版本只做准备，不导入、不验证付费接口、不修改线上配置，也不会把待核实记录标记为可发送。

```sh
python3 tools/contactout-visible-export/prepare_review.py \
  --csv /path/to/contactout-visible.csv \
  --benchmarks outputs/enterprise-rnd-filtered-20260914/benchmark_directory.json \
  --output outputs/contactout-review/review.json
```

`--online-audit` 可附加已取得的只读检查结果；历史快照仅用于解释当时的匹配情况，正式导入必须刷新。样例报告位于 `outputs/contactout-review-20260917/review.json`。

当前样例结果：**待审核 1 人，可发送 0 人**。下一步首先核实其云架构研发职责是否匹配本项目需求，再验证个人邮箱；不通过时应换符合技术方向的样本。
